# 文件内容补全

## 描述

补全文件内容，检查完整性并补充缺失信息，确保文档自解释，无需查阅源码即可理解。

## 使用场景

- 文档内容不完整，需要依据源码补充
- 缺少关键信息、参数说明、示例代码
- 图表缺少描述，需要补充核心结论
- 英文缩写需要补全全称

## 指令

### 内容补全规则

1. 检查当前文件的内容是否完整匹配源码中本章节聚焦的所有内容，如果不完整则依据源码进行补充
2. 补充缺失的关键信息、参数说明、示例代码等
3. 数值一定要带上可读性高的单位，需要保留原始数据和单位
4. 概念解释优化：补充问题背景、触发时机、优化方案、简要说明，增加可读性
5. 补充图表、代码中的变量/参数的默认值，并添加简要说明
6. 为复杂流程添加可视化图例
7. 表格/列表选择：可读性优先
8. 引用内容必须添加markdown锚点，尽量使用相对路径

### 自解释规则

文档内容应做到自解释，无需查阅源码即可理解：

1. **方法协作关系**：多个方法配合使用时，需说明调用时机和协作流程（如 `wakeup()` 与 `waitForRunning()`）
2. **回调触发方式**：回调方法需说明所有触发条件（如 `onWaitEnd()` 有定时执行和被唤醒执行两种方式）
3. **代码注释准确**：注释必须与实际逻辑一致，避免误导
4. **英文缩写补全**：首次出现时补全全称，格式：`中文全称(缩写，English Full Name)`

### 表格说明

- **枚举值**：状态/名称、值、说明、触发条件。复杂状态补充转换图
- **字段**：字段、示例值、说明

### 常用单位规范

| 类型 | 单位 |
|------|------|
| 时间 | ms、s、min、h |
| 大小 | B、KB、MB、GB |
| 数量 | 个、条、次 |

## 要求

1. 所有内容必须与源码一致，禁止凭记忆或推测编写
2. 统一标题、列表、代码格式

## 文档优化规则

### 内容合并规则

| 规则 | 说明 |
|------|------|
| 删除重复 | 相同内容只保留一处，避免冗余 |
| 合并同类 | 相似内容合并到同一章节 |
| 精简冗余 | 删除不常用的细节（如内核结构体的冷门字段） |

### 章节编排规则

| 规则 | 说明 |
|------|------|
| 层次清晰 | 从宏观到微观，从概念到实现 |
| 逻辑连贯 | 相关内容就近放置 |
| 编号统一 | 章节编号格式一致（3.1、3.2、3.2.1） |

### 图表优化规则

| 规则 | 说明 |
|------|------|
| 简洁优先 | 删除不必要的装饰元素 |
| 信息密度 | 一张图说清一个核心概念 |
| 表格精简 | 列数控制在5列以内 |

### 内容精简规则

| 规则 | 说明 |
|------|------|
| 保留核心 | 保留常用操作，删除冷门操作 |
| 一句话总结 | 每个章节有核心结论 |
| 代码示例 | 只保留关键代码，删除完整实现 |

### 优化原则

1. 不删除有用信息
2. 合并相同内容
3. 精简冗余细节
4. 保持逻辑清晰
5. 图表简洁明了
