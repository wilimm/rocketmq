# 源码解读技能

本技能帮助分析源码并创建准确、概念清晰的技术文档。

## 触发条件

当用户请求以下任务时调用本技能：

| 触发场景 | 示例请求 |
|----------|----------|
| 架构分析 | "分析这个系统的架构设计" |
| 模块解读 | "解释这个模块的工作原理" |
| 流程追踪 | "分析这个功能的实现流程" |
| 文档编写 | "为这个组件编写技术文档" |
| 概念梳理 | "梳理这个系统的核心概念" |

## 前置条件

使用本技能前需确认：

| 条件 | 说明 | 验证方法 |
|------|------|----------|
| 源码可访问 | 目标代码存在于工作目录 | LS/Glob 确认文件存在 |
| 语言可识别 | 代码语言在支持范围内 | 检查文件扩展名 |
| 范围明确 | 用户已指定分析范围 | 确认用户意图 |

## 输出目标

本技能输出符合以下标准的技术文档：

| 目标 | 说明 |
|------|------|
| 概念准确 | 所有概念定义与源码一致 |
| 结构清晰 | 适合新人阅读理解 |
| 可追溯 | 提供源码链接便于验证 |
| 实用性 | 包含快速参考和示例 |

## 执行步骤

按照以下顺序执行源码分析：

```mermaid
flowchart LR
    A[1.入口定位] --> B[2.结构梳理]
    B --> C[3.概念提取]
    C --> D[4.关系分析]
    D --> E[5.流程追踪]
    E --> F[6.源码核对]
    F --> G[7.文档输出]
```

### 步骤1：入口定位

确定分析的起点：

| 分析维度 | 定位方法 | 工具 |
|----------|----------|------|
| 主入口类 | 查找 `main` 方法或启动类 | Grep `public static void main` |
| 核心模块 | 查看构建文件 | Read `pom.xml` / `build.gradle` |
| 配置入口 | 查找配置类或属性文件 | Glob `**/application*.yml` |
| API入口 | 查找 Controller 或 Handler | Grep `@Controller|@RestController` |

### 步骤2：结构梳理

了解项目整体结构：

| 分析步骤 | 说明 | 工具 |
|----------|------|------|
| 目录结构 | 了解模块划分 | LS 查看目录 |
| 包结构 | 了解代码组织 | Glob `**/*.java` |
| 依赖关系 | 了解模块依赖 | Read 构建文件 |
| 继承关系 | 了解类层次 | Grep `extends|implements` |

### 步骤3：概念提取

从源码中提取核心概念：

| 概念来源 | 识别标志 |
|----------|----------|
| 领域实体 | `@Entity`、`@Document`、领域接口 |
| 核心接口 | 业务相关接口定义 |
| 枚举类型 | `enum` 关键字 |
| 常量定义 | `static final` |
| 配置项 | `@ConfigurationProperties`、配置文件 |

### 步骤4：关系分析

分析概念之间的关系：

| 关系类型 | 分析方法 | 工具 |
|----------|----------|------|
| 调用关系 | 方法调用链追踪 | SearchCodebase |
| 依赖关系 | import 语句分析 | Grep `import` |
| 继承关系 | extends/implements | Grep `extends\|implements` |
| 组合关系 | 字段类型分析 | Read 类文件 |

### 步骤5：流程追踪

追踪关键业务流程：

| 流程类型 | 追踪起点 | 追踪方法 |
|----------|----------|----------|
| 请求处理 | Controller 方法 | 跟踪方法调用链 |
| 数据流转 | 数据入口 | 跟踪数据读写 |
| 事件处理 | 事件发布点 | 跟踪监听器 |
| 定时任务 | `@Scheduled` | 跟踪任务执行 |

### 步骤6：源码核对

**核心原则：所有概念定义必须与源码内容保持一致，禁止凭记忆或推测编写。**

| 核对维度 | 核对方法 | 工具 |
|----------|----------|------|
| 类名/方法名 | 读取源码确认准确拼写 | Read 类文件 |
| 方法签名 | 确认参数类型、返回值、异常 | Read 方法定义 |
| 字段类型 | 确认字段声明和泛型类型 | Read 字段定义 |
| 注解信息 | 确认注解及其属性值 | Read 注解使用处 |
| 常量值 | 确认常量的实际值 | Read 常量定义 |
| 枚举项 | 确认枚举值和顺序 | Read 枚举类 |

#### 核对清单

在输出文档前，必须逐项核对：

| 核对项 | 核对内容 | 确认方式 |
|--------|----------|----------|
| **类名准确性** | 文档中的类名与源码完全一致 | Read 源文件确认 |
| **方法签名** | 方法名、参数、返回值与源码一致 | Read 方法声明 |
| **字段名称** | 字段名、类型与源码一致 | Read 字段声明 |
| **枚举值** | 枚举项名称与源码一致 | Read 枚举定义 |
| **常量值** | 常量值与源码一致 | Read 常量定义 |
| **继承关系** | extends/implements 与源码一致 | Read 类声明 |
| **调用链** | 方法调用顺序与源码一致 | SearchCodebase 追踪 |
| **配置项** | 配置键名与源码一致 | Read 配置文件 |

#### 常见错误示例

| 错误类型 | 错误示例 | 正确做法 |
|----------|----------|----------|
| 类名拼写错误 | `MessageQuee` (漏字母) | Read 源码确认 `MessageQueue` |
| 方法名错误 | `getMessage()` 实际是 `getMessageInfo()` | Read 方法定义确认 |
| 参数类型错误 | `String topic` 实际是 `TopicConfig topic` | Read 方法签名确认 |
| 枚举值错误 | `SYNC` 实际是 `Sync` | Read 枚举定义确认 |
| 继承关系错误 | "继承自 A" 实际是 "实现接口 B" | Read 类声明确认 |

按照标准结构输出文档：

## 质量检查

输出文档前，按以下顺序进行检查：

### 第一步：结构检查

| 检查项 | 要求 | 验证方法 |
|--------|------|----------|
| 章节完整 | 包含所有必需章节 | 对照文档模板核对 |
| 层次清晰 | 章节层级不超过4级 | 检查标题层级 |
| 逻辑连贯 | 章节顺序符合阅读习惯 | 从新人视角通读 |
| 结构合理 | 适合新人阅读理解 | 同行评审 |

### 第二步：内容检查

| 检查项 | 要求 | 验证方法 |
|--------|------|----------|
| 概念定义 | 全文一致，且与源码一致 | Read 源码核对 |
| 源码引用 | 路径正确，行号准确 | 点击链接验证 |
| 类名/方法名 | 与源码拼写完全一致 | Read 源码确认 |
| 方法签名 | 参数类型、返回值与源码一致 | Read 方法声明 |
| 字段类型 | 字段名、泛型类型与源码一致 | Read 字段定义 |
| 示例场景 | 统一贯穿全文 | 检查一致性 |
| 无重复内容 | 同一内容只出现一次 | 全文检索 |
| 术语统一 | 中英文一致 | 术语表核对 |
| **源码核对完成** | 所有概念已通过 Read 工具核对确认 | 核对清单 |

### 第三步：排版检查

| 检查项 | 要求 | 验证方法 |
|--------|------|----------|
| 表格对齐 | 列分隔符对齐整齐 | 视觉检查 |
| 代码块完整 | 代码块有正确的语言标识 | 检查 ``` 语法 |
| 链接有效 | 所有链接可点击跳转 | 逐个点击验证 |
| 图表渲染 | Mermaid 图表可正常渲染 | 预览检查 |
| 无多余空行 | 段落间空行不超过1行 | 视觉检查 |

## 最佳实践

### 分析技巧

| 技巧 | 说明 | 示例 |
|------|------|------|
| 自顶向下 | 先整体后局部，先架构后细节 | 先看模块结构，再深入具体类 |
| 追踪入口 | 从用户入口追踪完整调用链 | 从 Controller 追踪到 DAO |
| 对比分析 | 对比相似组件的差异 | 对比不同实现类的特点 |
| 注释优先 | 优先阅读类和方法的注释 | 了解设计意图 |

### 效率提升

| 方法 | 说明 |
|------|------|
| 批量读取 | 一次读取多个相关文件，减少工具调用次数 |
| 模式搜索 | 使用正则表达式批量查找模式 |
| 层次展开 | 先列出目录结构，再按需深入 |
| 复用结果 | 缓存已分析的概念定义，避免重复分析 |

## 常见问题处理

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 找不到入口类 | 项目结构复杂或入口分散 | 搜索 main 方法、查找启动脚本、检查构建文件 |
| 类名不确定 | 源码中有多个相似命名 | Read 源码确认完整类名和包路径 |
| 继承关系复杂 | 多层继承或实现多个接口 | 绘制类图梳理关系 |
| 流程分支多 | 业务逻辑复杂 | 先梳理主流程，再分析分支 |
| 配置项分散 | 配置在多个文件中 | 搜索配置文件模式，汇总整理 |
| 源码版本差异 | 分析版本与预期不符 | 确认 git 分支或版本号 |

## 注意事项

| 注意点 | 说明 |
|--------|------|
| 避免推测 | 所有信息必须来自源码，禁止凭记忆或推测 |
| 保持中立 | 客观描述实现，避免主观评价 |
| 及时核对 | 发现概念立即核对源码，不要批量核对 |
| 记录来源 | 每个概念标注源码位置，便于追溯 |
| 版本说明 | 文档开头说明分析的源码版本 |
