# 文件内容优化

## 1. 内容精简与重组规则

目标：**保持原文语义和关键信息的前提下，优化结构、补充缺失，提升完整性和可读性**

**重要：进行内容重组之前，先给出重组后的章节列表，让用户确认**

**核心原则：严禁随意删减有用内容！删除内容前必须确认该内容确实是冗余信息。**

### 1.1 内容处理

1. 代码精简：
   - 保留核心逻辑和关键实现细节，添加中文注释说明
   - 非核心逻辑用注释代替，格式：`// 非核心逻辑：xxx处理` 或 `// 省略：参数校验、异常处理等`
   - 仅删除明确的冗余代码（如重复的空行、无用的注释）
2. 内容聚合：相同主题内容放在一起，按逻辑顺序排列，**不删除任何有用信息**
3. 表述精简：仅删除明确的冗余修饰词，合并重复内容，**绝不省略任何关键要素和技术细节**
4. 术语统一：同一概念使用统一术语
5. **禁止删除**：技术细节、配置说明、参数描述、使用示例、注意事项、边界条件、异常情况说明等均不可删除

### 1.2 章节结构

1. 标题贴合内容：章节标题准确反映章节内容
2. 章节合并：相关内容合并，要求**高内聚、低耦合**
3. 层级适度：不限制层级深度，但建议扁平化处理，减少嵌套层级提升可读性
4. 边界清晰：每个章节聚焦单一主题
5. 概述精简：只保留文档开头的总概述

### 1.3 格式规范

1. 标题编号：所有标题必须带序号（一级：`1.`、二级：`1.1`、三级：`1.1.1`）
2. 标题优先：尽量用标题标记独立段落，少用加粗`**`，标题可以更好地对内容进行索引
3. 图表位置：描述和介绍信息放在图表下方
4. 列表统一：同类列表格式一致，层级缩进统一
5. 代码规范：指定语言类型，添加必要注释
6. 链接规范：使用相对路径，确保可点击。详见下方链接规范章节

#### 链接规范

源码链接使用相对路径，格式：`../模块名/src/.../文件名.java`。示例：`../common/src/main/java/Service.java`

### 1.4 内容组织

1. 先核心后实践：核心概念和架构优先，应用实践后置
2. 先整体后局部：从整体到局部、从抽象到具体
3. 依赖前置：被引用的内容放在前面
4. 引用明确：章节间引用时标注具体位置

## 2. 基本原则

1. 内容准确：所有内容必须与源码一致
2. 格式统一：统一标题、列表、代码格式
3. 语义不变：优化内容时不改变原文含义
4. 信息完整：不删除核心技术细节和重要说明，补充缺失内容
