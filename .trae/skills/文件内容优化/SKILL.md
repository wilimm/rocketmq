# 文件内容优化

## 1. 描述

优化文件内容，重组章节结构、补充缺失内容、规范格式，提升文档完整性和可读性。

**核心原则：严禁随意删减有用内容！删除内容前必须确认该内容确实是冗余信息。**

## 2. 使用场景

- 文档结构混乱，需要重组章节
- 文档内容不完整，需要补充缺失信息
- 文档格式不规范，需要统一格式
- 文档存在冗余内容，需要精简

## 3. 指令

**重要：进行内容重组之前，先给出重组后的章节列表，让用户确认**

### 3.1 内容处理原则

#### 3.1.1 保留优先原则

**宁可保留也不要误删！** 以下内容必须完整保留：

| 内容类型 | 说明 | 示例 |
|---------|------|------|
| 技术细节 | 核心技术原理、实现机制 | mmap映射原理、epoll触发模式 |
| 配置参数 | 参数名称、默认值、最优配置、说明 | mappedFileSizeCommitLog=1GB |
| 使用示例 | 代码示例、配置示例、使用场景 | 参数配置示例、调优案例 |
| 注意事项 | 重要约束、边界条件、风险提示 | 参数过大导致映射开销大 |
| 对比说明 | 不同方案的对比、优缺点分析 | 同步刷盘 vs 异步刷盘 |
| 性能数据 | 性能指标、基准测试结果 | 顺序写比随机写快10-100倍 |
| 架构图表 | 系统架构、数据流图、状态转换图 | 四层架构图、Reactor模型图 |

#### 3.1.2 代码精简原则

**仅精简过长的代码块，且必须保留关键逻辑：**

| 类型 | 处理方式 | 示例 |
|------|---------|------|
| 可精简 | 重复的getter/setter、标准异常处理模板、日志打印（保留关键）、参数校验（用注释说明） | `// 省略参数校验` |
| 必须保留 | 核心业务逻辑、关键算法、并发控制、资源管理、错误恢复 | 锁、CAS、同步块 |

精简示例：

```java
public void coreMethod() {
    // 核心步骤1：初始化资源
    Resource resource = initResource();
    // 省略：参数校验、异常处理
    // 核心步骤2：执行业务逻辑
    doBusiness(resource);
    // 核心步骤3：释放资源
    releaseResource(resource);
}
```

#### 3.1.3 表述精简原则

| 可精简 | 不可精简 |
|--------|---------|
| 重复修饰词（"非常"、"极其"） | 技术细节描述 |
| 完全重复的段落 | 配置参数说明 |
| 过度的格式说明 | 使用场景说明、注意事项 |

### 3.2 章节结构规范

| 规范 | 说明 |
|------|------|
| 标题贴合内容 | 章节标题准确反映章节内容 |
| 章节合并 | 相关内容合并，高内聚、低耦合 |
| 层级适度 | 建议扁平化处理，减少嵌套层级 |
| 边界清晰 | 每个章节聚焦单一主题 |
| 概述精简 | 只保留文档开头的总概述 |

### 3.3 格式规范

| 规范项 | 要求 |
|--------|------|
| 标题编号 | 所有标题必须带序号（一级：`1.`、二级：`1.1`、三级：`1.1.1`） |
| 标题优先 | 尽量用标题标记独立段落，少用加粗`**` |
| 图表位置 | 描述和介绍信息放在图表下方 |
| 列表统一 | 同类列表格式一致，层级缩进统一 |
| 代码规范 | 指定语言类型，添加必要注释 |
| 链接规范 | 使用相对路径，格式：`../模块名/src/.../文件名.java` |

### 3.4 内容组织原则

1. **先核心后实践**：核心概念和架构优先，应用实践后置
2. **先整体后局部**：从整体到局部、从抽象到具体
3. **依赖前置**：被引用的内容放在前面
4. **引用明确**：章节间引用时标注具体位置
