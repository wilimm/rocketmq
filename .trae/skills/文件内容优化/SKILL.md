# 文件内容优化

## 1. 内容精简与重组规则

目标：**保持原文语义和关键信息的前提下，优化结构、补充缺失，提升完整性和可读性**

**重要：进行内容重组之前，先给出重组后的章节列表，让用户确认**

**核心原则：严禁随意删减有用内容！删除内容前必须确认该内容确实是冗余信息。**

### 1.1 内容处理

1. 代码精简：保留核心逻辑和关键实现细节，仅删除明确的冗余代码（如重复的空行、无用的注释），添加中文注释
2. 内容聚合：相同主题内容放在一起，按逻辑顺序排列，**不删除任何有用信息**
3. 表述精简：仅删除明确的冗余修饰词，合并重复内容，**绝不省略任何关键要素和技术细节**
4. 术语统一：同一概念使用统一术语
5. 内容补全：补充缺失的关键信息、参数说明、示例代码等
6. **禁止删除**：技术细节、配置说明、参数描述、使用示例、注意事项、边界条件、异常情况说明等均不可删除

### 1.2 章节结构

1. 标题贴合内容：章节标题准确反映章节内容
2. 章节合并：相关内容合并，要求**高内聚、低耦合**
3. 层级适度：一般不超过三级，避免过度嵌套
4. 边界清晰：每个章节聚焦单一主题
5. 概述精简：只保留文档开头的总概述

### 1.3 格式规范

1. 标题编号：所有标题必须带序号（一级：`1.`、二级：`1.1`、三级：`1.1.1`）
2. 图表位置：描述和介绍信息放在图表下方
3. 列表统一：同类列表格式一致，层级缩进统一
4. 代码规范：指定语言类型，添加必要注释
5. 链接规范：使用相对路径，确保可点击。详见下方链接规范章节
6. 补充图表、代码中的变量/参数的默认值，并添加简要说明，增加可读性
7. **英文缩写补全**：首次出现英文缩写时，需补全英文全称
8. **枚举值详细说明**：当文档中出现枚举值时，需按以下规则展开说明

#### 英文缩写规范

**格式**：`中文全称(缩写，English Full Name)`

**规则**：

1. 首次出现缩写时必须补全英文全称
2. 同一文档内后续出现相同缩写时，无需重复补全

示例参见 [examples/英文缩写示例.md](examples/英文缩写示例.md)

#### 枚举值说明规范

**表格格式**：

| 列名 | 说明 | 必填 |
|------|------|------|
| 状态/名称 | 枚举值名称 | ✅ |
| 值 | 枚举值对应的数值或常量 | ✅ |
| 说明 | 枚举值的含义描述 | ✅ |
| 触发条件 | 进入该状态/值的条件 | 可选 |

**补充内容**：

1. **状态转换图**：使用Mermaid `stateDiagram-v2` 展示状态之间的转换关系
2. **映射关系表**：如果存在不同系统/语言之间的状态映射，需补充映射表
3. **关键概念**：对特殊术语进行简要解释

示例参见 [examples/枚举值说明示例.md](examples/枚举值说明示例.md)

#### 字段说明规范

**表格格式**：

| 列名 | 说明 | 必填 |
|------|------|------|
| 字段 | 字段名称 | ✅ |
| 示例值 | 字段对应的典型值或默认值 | ✅ |
| 说明 | 字段的含义描述 | ✅ |

示例参见 [examples/字段说明示例.md](examples/字段说明示例.md)

#### 链接规范

源码链接使用相对路径，格式：`../模块名/src/.../文件名.java`。示例：`../common/src/main/java/Service.java`

### 1.4 内容组织

1. 先核心后实践：核心概念和架构优先，应用实践后置
2. 先整体后局部：从整体到局部、从抽象到具体
3. 依赖前置：被引用的内容放在前面
4. 引用明确：章节间引用时标注具体位置

## 常用单位规范

| 类型 | 单位 |
|------|------|
| 时间 | ms、s、min、h |
| 大小 | B、KB、MB、GB |
| 数量 | 个、条、次 |

## 2. 基本原则

1. 内容准确：所有内容必须与源码一致
2. 格式统一：统一标题、列表、代码格式
3. 语义不变：优化内容时不改变原文含义
4. 信息完整：不删除核心技术细节和重要说明，补充缺失内容
