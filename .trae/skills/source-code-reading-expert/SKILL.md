# 一、技能基础信息（定位+核心规则）
## 1.1 技能定位
专为Trae当前打开项目提供全流程源码解析，遵循「生成-可修改-确认执行-输出前核对-最终输出」核心逻辑，100%忠于官方来源，仅4处必要交互，分3步生成可归档文档。

## 1.2 核心规则（无例外）
1.  模块划分：遵循「高内聚、低耦合+数量足够小」，禁止违规拆分/合并；
2.  修改规则：第1、2步文件支持交互式/手动随时修改，保存即生效，无需重生成；
3.  第3步逻辑：读取第1、2步最新内容，用户确认后一次性无交互输出；
4.  路径规则：默认输出至./docs，首次确认路径，后续复用；
5.  引用规范：仅第2、3步可添加跳转链接（项目内相对路径，不支持行号），第1步禁止添加；
6.  核对规则：输出前逐项核对，确保无违规、无遗漏、无偏差，未核对不得输出。

# 三、核心流程（3步闭环，可落地）
## 3.1 第1步：模块文档规划（定边界）
### 前置交互
仅首次询问路径：文档默认存储在./docs，是否需要调整路径？
可选回复：默认用./docs；自定义路径；未明确则默认。

### 核心目标
生成模块清单、全局校验规则、API依赖标注，作为文档基础框架，可随时修改，不添加任何跳转链接；生成后核对无误再保存。

### 输出文件
[确认路径]/00-模块文档规划.md（文件名、路径固定），不添加跳转链接。

### 模块划分核心准则（强制）
1.  高内聚：模块内功能围绕同一职责，无无关内容；
2.  低耦合：模块间仅通过接口交互，减少直接依赖；
3.  数量足够小：满足前两项的前提下，不拆分过细；
4.  贴合项目：标注模块对应源码相对路径（无行号），为后续跳转链接提供基础。

### 修改规则
1.  修改方式：① 交互式：多轮口述修改；② 手动编辑，无限次修改，保存即生效；
2.  修改约束：可修改模块划分（遵准则）、清单内容；不可改核心结构、文件名/路径，禁止添加跳转链接；
3.  必含内容：划分准则、模块清单（表格固定）、全局校验规则（含源码路径标注要求）；
4.  核对要求：修改后核对，确保无违规、无遗漏，重点确认未添加跳转链接。

1.  自动读取第1、2步最新文件，异常时回退初始版本并标注；
2.  按模块清单生成文档，适配示例与格式规范；
3.  引用源码、文件、API时，仅第2、3步添加合规跳转链接，第1步相关内容不添加；
4.  源码路径错误时，标注链接失效，不中断流程；
5.  输出前核对：生成所有文档后逐项核对，确认无误再一次性输出。

### 输出文件

### 每个最终文档必含内容

-  架构/流程图表（优先Mermaid），贴合项目逻辑；（Mermaid渲染要求：使用规范语法，图表类型仅限graph、flowChart、sequenceDiagram、gantt、classDiagram、gitGraph、erDiagram、journey、quadrantChart、xychart-beta，代码块需正确包裹，无语法错误）

-  匹配统一示例，引用时添加合规跳转链接；
-  底层API统一引用公共文件，标注来源（如有）；

-  模块总结，引用模块规划文档时不添加跳转链接；
-  核对标识：末尾标注「已完成输出前核对，符合本技能所有既定要求（仅第2、3步添加跳转链接）」。

# 四、输出标准与专项规则（规范约束）

-  源码保真：完全忠于项目源码/API官方来源，不编造、不臆测；
-  模块规范：贴合项目架构，无冗余、无细碎模块，符合划分准则；
-  修改灵活：第1、2步文件可随时修改，自动覆盖，第3步读取最新版本；
-  交互规范：仅路径、两步修改、三步执行4处交互，话术简洁固定；
-  格式统一：数字带原始值+单位+注释（时间/大小类必加），图表仅用Mermaid、ASCII；示例：120000ms（2分钟，Broker心跳超时时间）；Mermaid图表需遵循规范语法，确保可正常渲染；
-  可归档性：文件名、结构固定，统一存储，可直接保存使用；
-  引用规范：仅第2、3步添加跳转链接（相对路径，不支持行号），路径准确；第1步禁止添加；
-  核对标准：输出前完成全面核对，确保无违规、无遗漏、无偏差，未核对不得输出。

## 4.2 专项规范规则（无例外）
### （一）路径交互规则
仅首次询问路径，自定义路径不可访问时回退至./docs并提示；文件统一存储，保障跳转链接准确；输出前核对路径表述及第1步无跳转链接。

### （二）随时修改规则（第1、2步适用）
1.  核心原则：可随时、无限次修改，保存即生效，第3步读取最新版本；
2.  修改方式规范：
| 修改方式 | 操作流程 | 适用场景 | 注意事项 |
|----------|----------|----------|----------|
| 交互式修改 | 生成→询问→修改→更新→核对→保存 | 快速简单修改 | 第1步禁止添加跳转链接；第2步确保跳转链接合规，修改后先核对再保存 |
| 手动修改 | 打开→编辑→核对→保存 | 复杂批量修改 | 第1步禁止添加跳转链接；第2步确保源码路径准确，修改后先核对再保存 |
3.  生效约束：修改后覆盖原文件，可交叉使用两种方式；严禁违规修改，核对无误方可生效。

### （三）第3步执行确认规则
询问话术含路径，仅接受「是」「否」；确认后一次性输出，异常回退标注；终止时提示明确；输出前核对执行逻辑及跳转链接规则。

### （四）系统API补充规则
1.  补充优先级：官方源码仓库→官方文档→权威开源社区；
2.  标注要求：补充内容标注来源（仅第2、3步添加合规跳转链接，第1步不添加），区分项目自有与API代码；
3.  异常处理：未查询到权威来源时，标注说明，不编造内容；
4.  核对要求：输出前核对API补充内容，确保来源权威、标注规范、跳转链接合规。

### （五）数字与单位规则
数字需含原始值+单位+注释（时间/大小类必加）；时间类数字标注完整信息；输出前核对，确保无遗漏、无错误；示例：120000ms（2分钟，Broker心跳超时时间）。

### （六）跨文件引用规则
公共内容集中在《07-底层公共组件-API-工具类.md》，其他文件仅引用不重复；仅第2、3步添加合规跳转链接，第1步不添加；输出前核对引用逻辑。

### （七）图表规范规则（重点保障Mermaid可渲染）
1.  图表类型：仅使用Mermaid（优先）、ASCII图表；Mermaid仅限支持的图表类型：graph、flowChart、sequenceDiagram、gantt、classDiagram、gitGraph、erDiagram、journey、quadrantChart、xychart-beta，禁止使用其他类型。
2.  语法要求：Mermaid代码需符合官方规范，避免语法错误（如箭头后需跟+、-或合法ACTOR，角色需提前定义，关键字大小写正确）；示例：正确语法「actor Create\nMain->>Create: 创建并启动 Control」或「Main->>+Create: 创建并启动 Control」。
3.  渲染保障：箭头贴合流程逻辑，添加清晰标题；Mermaid代码块需正确包裹，无多余字符、无缺失符号；输出前需专门核对Mermaid语法，确保可正常渲染。
4.  关联要求：关联文件仅第2、3步添加合规跳转链接；输出前核对图表合规性及Mermaid渲染可行性。

### （八）Markdown跳转链接专项规范（仅第2、3步适用）
1.  格式：「[链接显示文本](目标完整相对路径)」，显示文本优先用文件名/API来源名，无行号，禁止添加行号参数；
2.  适用范围：覆盖第2、3步所有引用场景，项目内统一用相对路径，异常链接标注失效；第1步禁止添加；
3.  引用规范：首次引用添加链接，后续重复不添加，避免冗余；
4.  核对要求：输出前逐项核对，确保格式正确、路径合规、无行号、异常标注无误，同时确认第1步无跳转链接。

### （九）输出前核对专项规则（核心）
#### 1. 核对时机
- 第1、2步：文件生成后、修改后保存前，针对性核对；
- 第3步：所有最终文档生成后、输出前，全面核对。

#### 2. 核对范围（全覆盖）
1.  源码保真：无编造、无臆测，与项目源码/官方来源一致；
2.  模块规范：符合「高内聚、低耦合+数量足够小」准则；
3.  修改规则：第1、2步修改无违规，第1步无跳转链接，第2步跳转合规；
4.  交互规范：仅4处必要交互，话术固定简洁；
5.  格式统一：数字、单位、图表符合规范，可直接渲染；重点核对Mermaid语法及渲染可行性；
6.  引用规范：跳转链接格式正确、路径合规、无行号，仅第2、3步添加，第1步无遗漏；
7.  路径规则：路径与用户确认一致，无重复询问；
8.  可归档性：文档结构、文件名固定统一；
9.  其他规则：符合通用强制质量规则、铁律约束、异常处理规则。

#### 3. 核对处理逻辑
1.  核对无误：执行后续操作（保存/输出），第3步文档添加核对标识；
2.  发现违规/遗漏：
    -  可自动修正（链接格式、数字单位、行号、第1步误加跳转、Mermaid简单语法错误等）：修正后重新核对，直至无误；
    -  不可自动修正（模块违规、编造内容、Mermaid严重语法错误等）：终止操作，提示「核对发现违规内容（具体类型：XXX），已终止，请调整后重新触发」；
3.  核对记录：留存简要记录（时机、结果、修正内容），随文档存储，便于追溯。

13. 输出前必须完成全面核对，未核对或核对违规不得输出。

## 5.2 铁律约束（违规直接终止，无例外）
严禁编造内容、违反模块准则、修改关键文件信息、第3步未确认即执行、API补充不标注来源、数字不规范、使用非规定图表、使用违规Mermaid语法（导致无法渲染）、重复描述公共内容、修改后违反保真规则、中断输出、冗余交互、第2/3步未添加跳转链接/链接失效未标注、输出前未核对/核对违规仍输出、跳转链接非相对路径/含行号、第1步添加跳转链接。

## 5.3 异常处理规则（全覆盖，不中断流程）
1.  路径异常：自定义路径不可用，回退至./docs并提示；
2.  文件异常：第1、2步文件异常，回退初始版本并标注；第1步无跳转链接，第2步跳转失效标注；
3.  API补充异常：未查询到来源，标注说明；
4.  模块修改异常：违反准则，提示调整，拒绝保存或标注违规；
5.  交互异常：未明确回复，按默认处理（路径用./docs，不执行修改/生成）；
6.  修改同步异常：文件未保存，读取上一版本并标注；
7.  跳转链接异常：第2、3步链接失效标注；非相对路径/含行号/第1步误加，按核对异常处理；
8.  核对异常：
    -  自动修正后仍不合规：终止操作，提示具体违规内容；
    -  不可自动修正违规：终止并告知违规类型，引导调整；
    -  核对记录异常：不影响输出，标注「核对记录留存异常，文档内容已核对无误」；
9.  Mermaid渲染异常：若核对发现Mermaid语法错误导致无法渲染，属于可自动修正范围的立即修正，无法自动修正的终止操作，提示「Mermaid语法违规，无法渲染，请调整后重新触发」。
