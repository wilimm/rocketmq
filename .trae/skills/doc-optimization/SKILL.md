# 文档优化技能

## 执行步骤

```mermaid
flowchart LR
    A[1.结构审查] --> B[2.内容审查]
    B --> C[3.源码核对]
    C --> D[4.优化执行]
    D --> E[5.审查报告]
```

### 步骤1：结构审查

#### 1.1 章节结构检测

| 检测类型 | 判断标准 | 处理方式 |
|----------|----------|----------|
| 章节标题重复 | 关键词重叠 > 50% | 合并到首次出现章节 |
| 层次过深 | 子章节层级 > 3 层 | 扁平化或提取为独立章节 |
| 层次过浅 | 一级章节 > 12 个 | 按主题分组 |
| 粒度过粗 | 单章节行数 > 500 或子章节 > 6 个 | 按子主题拆分 |
| 粒度过细 | 单章节行数 < 50 且无独立价值 | 合并到父章节 |
| 主题混杂 | 同一章节包含多个不相关主题 | 按主题拆分 |

#### 1.2 标题简要说明

每个章节标题后应紧跟简要说明（1-2句话）：

| 标题类型 | 模板 |
|----------|------|
| 类/接口 | `XXX 是...的核心类/接口，用于...` |
| 机制/策略 | `XXX 是一种...机制，用于解决...问题` |
| 流程 | `本节描述...的完整流程` |
| 配置 | `XXX 用于配置...` |

### 步骤2：内容审查

#### 2.1 重复内容检测

| 检测类型 | 处理方式 |
|----------|----------|
| 表格/代码重复 | 删除重复，改为引用 |
| 配置参数重复 | 删除重复，改为引用 |
| 跨章节重复 | 保留最完整版本，其他改为引用 |
| 跨文件重复 | 保留最完整版本，其他改为引用 |

**引用格式**：`详见 [文档名 - 章节名](./文件名.md#章节锚点)`

#### 2.2 内容归属检测

| 问题类型 | 判断标准 | 处理方式 |
|----------|----------|----------|
| 主题偏移 | 内容与章节标题关联度 < 50% | 移动到相关章节 |
| 层级错位 | 子内容重要性超过父章节 | 提升为独立章节 |
| 归属错位 | 实现细节放在概念章节 | 移动到正确归属章节 |
| 前置缺失 | 引用概念未在前文定义 | 补充定义或调整顺序 |

**归属原则**：概念→概念篇，流程/实现→实现篇，配置项→配置章节，示例→实践章节。

#### 2.3 跨文件内容归属

| 内容类型 | 归属位置 | 判断依据 |
|----------|----------|----------|
| 模块专属行为 | 模块对应文档 | 与模块强相关的内容 |
| 共享组件 | 首次出现文件 + 引用 | 多模块共用的基础组件 |
| 对比内容 | 主要角色所在文件 | 以一方为主的对比分析 |

**跨文件移动规范**：

1. 确定目标文件和章节位置
2. 在目标文件添加完整内容
3. 在源文件保留简要说明 + 引用链接
4. 更新目标文件总结部分
5. 验证双向引用正确性

**引用示例**：

```markdown
# 源文件（精简后）
> **详细机制详见**：[目标文档 - 章节名](./目标文件.md#章节锚点)

# 目标文件（完整内容）
> **相关概念详见**：[源文档 - 章节名](./源文件.md#章节锚点)
```

#### 2.4 可合并内容检测

| 问题类型 | 合并方式 |
|----------|----------|
| 相邻小章节 | 合并为一个章节 |
| 同主题分散 | 合并到首次出现章节 |
| 概念与实现分离 | 概念在前，实现紧随其后 |
| 配置/示例分散 | 集中到一个章节 |

**合并优先级**：完全重复 > 强关联内容 > 同主题分散 > 相邻小章节

#### 2.5 术语一致性

| 检测类型 | 处理方式 |
|----------|----------|
| 术语不一致 | 统一为最完整表述 |
| 流程图与章节不一致 | 同步更新 |
| 概述与详述矛盾 | 以详述为准修正 |

**术语统一示例**：

| 统一前 | 统一后 | 说明 |
|--------|--------|------|
| 静态主题、静态 Topic | 静态 Topic | 统一使用中英文混合形式 |
| 偏移量、位点 | 偏移量（队列）、消费位点 | 区分不同场景使用 |

#### 2.6 内容类型与归属判断

| 内容类型 | 归属位置 | 示例 |
|----------|----------|------|
| 数据结构定义 | 核心概念篇 | 类字段、枚举值、常量定义 |
| 使用场景说明 | 高级特性篇 | 场景对比、典型应用案例 |
| 命令/代码示例 | 高级特性篇 | 创建命令、迁移命令、代码片段 |
| 配置项说明 | 配置章节 | 参数含义、默认值、单位 |

**移动操作规范**：

1. **确定移动范围**：识别内容类型，判断正确归属
2. **目标位置添加**：在目标文件对应章节添加完整内容
3. **源位置精简**：保留简要说明 + 引用链接
4. **更新引用**：确保双向引用正确

**移动示例**：

```markdown
# 核心概念篇（精简后）
> **应用场景**：静态 Topic 允许跨 Broker 分片...详细使用场景、命令示例、迁移流程详见 [高级特性篇 - 静态 Topic](06-高级特性篇.md#十静态-topic)。

# 高级特性篇（完整内容）
### 10.1 使用场景
| 场景 | 说明 | 静态 Topic 优势 |
...
**普通主题 vs 静态 Topic**：
...
**典型场景：两地三中心容灾部署**：
...
```

### 步骤3：源码核对（必做）

**核心原则：所有概念定义必须与源码一致，禁止凭记忆或推测编写。**

| 核对维度 | 核对方法 |
|----------|----------|
| 类名/方法名/签名 | 确认拼写、参数类型、返回值、异常 |
| 字段类型 | 确认字段声明和泛型类型 |
| 注解/常量/枚举 | 确认属性值、常量值、枚举值和顺序 |
| 配置项默认值 | 确认字段初始化值或 `@Value` 默认值 |

**常见错误**：枚举写成String、布尔写成int、泛型遗漏、默认值/单位错误、数值缺少单位。

### 步骤4：优化执行

| 操作类型 | 说明 |
|----------|------|
| 合并/拆分章节 | 将相关内容合并或过大章节拆分 |
| 移动内容 | 将内容移动到正确的归属位置 |
| 补充说明 | 为标题添加简要说明 |
| 修正错误 | 修正与源码不一致的内容 |
| 添加引用 | 将重复内容改为引用链接 |

**源码链接格式**：`类名 ([ClassName.java](file:///path/to/ClassName.java))`

**概念完整性标准**：数据类需包含所有字段、枚举类需包含所有枚举值、配置类需包含所有配置项及默认值、接口类需包含所有方法签名。

### 步骤5：审查报告

**审查清单**：

| 审查类别 | 审查项 |
|----------|--------|
| 结构 | 章节完整、层次清晰、粒度适中 |
| 内容 | 无重复、归属正确、术语一致 |
| 源码 | 字段/枚举/默认值一致、数值带单位 |
| 完整性 | 源码链接完整、核心概念属性完整 |

**报告格式**：

```markdown
## [文件名] 审查报告

### 审查结果
| 审查类别 | 状态 | 问题数量 |
|----------|------|----------|
| 结构 | ✅/⚠️/❌ | N |

### 问题列表
| 序号 | 问题类型 | 位置 | 描述 | 处理方式 |

### 优化记录
| 序号 | 操作类型 | 位置 | 内容摘要 |
```

---

## 注意事项

- 所有信息必须来自源码，禁止凭记忆或推测，每个概念标注源码位置
- 优化前备份原文档内容，优化后验证文档可读性和逻辑性
- 跨文件优化时注意引用关系的正确性
