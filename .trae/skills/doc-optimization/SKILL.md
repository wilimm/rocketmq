# 文档优化技能

## 执行步骤

```mermaid
flowchart LR
    A[1.完整性审查] --> B[2.结构审查]
    B --> C[3.内容审查]
    C --> D[4.源码核对]
    D --> E[5.优化执行]
    E --> F[6.审查报告]
```

---

## 步骤1：完整性审查

### 1.1 文件内容完整性检测

| 检测类型 | 判断标准 | 处理方式 |
|----------|----------|----------|
| 章节缺失 | 概述中提及但无对应章节 | 补充缺失章节 |
| 属性缺失 | 类/接口描述中遗漏字段或方法 | 从源码补充完整属性 |
| 枚举值缺失 | 枚举类描述中遗漏枚举值 | 从源码补充所有枚举值 |
| 配置项缺失 | 配置类描述中遗漏配置项 | 从源码补充所有配置项 |
| 参数缺失 | 方法描述中遗漏参数说明 | 从源码补充参数类型和说明 |

### 1.2 默认值与默认参数检测

| 检测类型 | 处理方式 |
|----------|----------|
| 配置项缺少默认值 | 从源码查找字段初始化值或 `@Value` 默认值并补充 |
| 方法参数缺少默认值说明 | 从源码查找方法重载或默认参数并补充 |
| 枚举值缺少说明 | 补充每个枚举值的含义和使用场景 |

示例修正：
- 修正前：`maxMessageSize 消息最大大小`
- 修正后：`maxMessageSize 消息最大大小，默认值 4MB`

---

## 步骤2：结构审查

### 2.1 章节结构检测

| 检测类型 | 判断标准 | 处理方式 |
|----------|----------|----------|
| 章节标题重复 | 关键词重叠 > 50% | 合并到首次出现章节 |
| 层次过深/浅 | 层级 > 3 或一级章节 > 12 | 扁平化或分组 |
| 粒度过粗/细 | 行数 > 500 或 < 50 | 拆分或合并 |
| 主题混杂 | 同章节多主题 | 按主题拆分 |

### 2.2 结构一致性检测

章节安排必须与概述/架构图/对比表格保持一致。

| 检测类型 | 判断标准 | 处理方式 |
|----------|----------|----------|
| 概述与章节不一致 | 概述中并列的概念，章节中变成从属关系 | 独立成章，保持并列 |
| 架构图与章节不一致 | 架构图中同级组件，章节中层级不同 | 调整章节层级 |
| 对比表格与章节不一致 | 表格中并列的行/列，章节中组织方式不同 | 重新组织章节结构 |

### 2.3 编号一致性检测

子章节编号必须与父章节编号匹配。

| 检测类型 | 处理方式 |
|----------|----------|
| 父子编号不匹配 | 修正子章节编号 |
| 编号跳跃 | 插入缺失章节或调整编号 |
| 编号重复 | 重新编号 |

### 2.4 标题简要说明

每个章节标题后应紧跟简要说明（1-2句话）：

| 标题类型 | 模板 |
|----------|------|
| 类/接口 | `XXX 是...的核心类/接口，用于...` |
| 机制/策略 | `XXX 是一种...机制，用于解决...问题` |
| 流程 | `本节描述...的完整流程` |

## 步骤3：内容审查

### 3.1 关键流程图例检测

关键流程必须配有流程图，便于读者理解。

| 检测类型 | 判断标准 | 处理方式 |
|----------|----------|----------|
| 核心流程无图例 | 消息发送/接收/存储等核心流程无流程图 | 使用 Mermaid 补充流程图 |
| 状态机无图例 | 状态转换逻辑无状态图 | 使用 Mermaid 补充状态图 |
| 时序交互无图例 | 多组件交互流程无时序图 | 使用 Mermaid 补充时序图 |
| 架构说明无图例 | 架构描述无架构图 | 使用 Mermaid 补充架构图 |

图例类型选择：
- 流程图（flowchart）：用于描述业务流程、决策流程
- 时序图（sequenceDiagram）：用于描述组件间交互、API调用
- 状态图（stateDiagram-v2）：用于描述状态转换、生命周期
- 架构图（flowchart/C4）：用于描述系统架构、模块关系

### 3.2 代码精简与注释检测

| 检测类型 | 判断标准 | 处理方式 |
|----------|----------|----------|
| 代码过长 | 代码块超过 30 行 | 精简为核心逻辑，删除非关键代码 |
| 代码缺少中文注释 | 代码块无中文注释 | 添加关键行中文注释 |
| 代码格式混乱 | 缩进不一致、空行过多 | 统一代码格式 |
| 代码与说明脱节 | 代码示例与文字说明不对应 | 调整代码或补充说明 |

代码精简原则：
- 保留核心逻辑，删除异常处理、日志打印等非关键代码
- 使用 `// ...` 省略非关键代码
- 关键行必须添加中文注释

示例修正：
```java
// 修正前（过长）
public PutMessageResult putMessage(final MessageExtBrokerInner msg) {
    long beginTime = this.defaultMessageStore.now();
    if (null == msg.getTopic()) {
        return new PutMessageResult(PutMessageStatus.MESSAGE_ILLEGAL, null);
    }
    if (msg.getTransactionId() != null) {
        // ... 大量代码
    }
    // ... 更多代码
}

// 修正后（精简 + 中文注释）
public PutMessageResult putMessage(final MessageExtBrokerInner msg) {
    // 1. 消息校验
    if (null == msg.getTopic()) {
        return new PutMessageResult(PutMessageStatus.MESSAGE_ILLEGAL, null);
```

### 3.3 数值单位检测

| 检测类型 | 判断标准 | 处理方式 |
|----------|----------|----------|
| 数值缺少单位 | 数值后无单位（如 `1000`） | 补充单位（如 `1000ms`） |
| 单位可读性差 | 使用小单位数值过大（如 `60000ms`） | 转换为大单位（如 `60s` 或 `1min`） |
| 单位不一致 | 同类数值使用不同单位 | 统一单位表述 |

常用单位规范：
- 时间：ms（毫秒）、s（秒）、min（分钟）、h（小时）
- 大小：B（字节）、KB、MB、GB
- 数量：个、条、次

示例修正：
- 修正前：`超时时间 30000`
- 修正后：`超时时间 30s`
- 修正前：`文件大小 10485760`
- 修正后：`文件大小 10MB`

### 3.4 重复内容检测

| 检测类型 | 处理方式 |
|----------|----------|
| 表格/代码/配置重复 | 删除重复，改为引用 |
| 跨章节/文件重复 | 保留最完整版本，其他改为引用 |

引用格式：`详见 [文档名 - 章节名](./文件名.md#章节锚点)`

### 3.5 内容归属检测

归属原则：概念→概念篇，流程/实现→实现篇，配置项→配置章节，示例→实践章节。

| 内容类型 | 归属位置 |
|----------|----------|
| 数据结构定义 | 核心概念篇 |
| 使用场景/命令示例 | 高级特性篇 |
| 配置项说明 | 配置章节 |
| 模块专属行为 | 模块对应文档 |
| 共享组件 | 首次出现文件 + 引用 |

跨文件移动规范：确定目标位置 → 目标文件添加完整内容 → 源文件保留简要说明+引用链接 → 验证双向引用。

### 3.6 内容整合检测

| 问题类型 | 整合方式 |
|----------|----------|
| 表格重叠 | 合并为一个表格 |
| 内容重复 | 合并为一个段落 |
| 架构图冗余 | 保留其一，另一个精简 |
| 代码分散 | 合并为单一代码块 |

整合原则：专注单一职责、删除冗余内容、精简源码展示。

### 3.7 图表精简检测

图表应以清晰易懂为主，避免冗余和过度装饰，但不能为了简洁而丢失关键信息。

| 检测类型 | 判断标准 | 处理方式 |
|----------|----------|----------|
| 图表冗余 | 同一概念用多图表达 | 保留最清晰的一张 |
| 图表过于复杂 | 超过 40 行或包含过多细节 | 拆分或精简，但保留关键结构 |
| 图表与表格重复 | 图表内容与表格完全相同 | 保留表格，删除图表 |

### 3.8 章节简要说明检测

| 检测类型 | 处理方式 |
|----------|----------|
| 缺少简要说明 | 添加 1-2 句简要说明 |
| 说明过长（超过 3 句话） | 精简为核心要点 |
| 说明与内容不符 | 修正说明 |

### 3.9 术语一致性

| 检测类型 | 处理方式 |
|----------|----------|
| 术语不一致 | 统一为最完整表述 |
| 流程图与章节不一致 | 同步更新 |
| 概述与详述矛盾 | 以详述为准修正 |

### 3.10 内容流畅度检测

章节内容应按"基础概念 → 核心流程 → 优化方案 → 扩展场景"的逻辑递进。

| 问题类型 | 判断标准 | 重组策略 |
|----------|----------|----------|
| 逻辑跳跃 | 前后章节主题关联弱 | 添加过渡章节或调整顺序 |
| 主题混杂 | 同一章节包含多个独立主题 | 按主题拆分为独立章节 |
| 层级倒置 | 优化方案先于核心流程出现 | 调整章节顺序 |
| 交叉引用过多 | 章节间频繁互相引用 | 合并相关章节 |
| 粒度不均 | 相邻章节详细程度差异大 | 过细章节合并，过粗章节拆分 |

## 步骤4：源码核对（必做）

所有概念定义必须与源码一致，禁止凭记忆或推测编写。

| 核对维度 | 核对方法 |
|----------|----------|
| 类名/方法名/签名 | 确认拼写、参数类型、返回值、异常 |
| 字段类型 | 确认字段声明和泛型类型 |
| 注解/常量/枚举 | 确认属性值、常量值、枚举值和顺序 |
| 配置项默认值 | 确认字段初始化值或 `@Value` 默认值 |

常见错误：枚举写成String、布尔写成int、泛型遗漏、默认值/单位错误、数值缺少单位、延迟/超时时间缺失。

### 4.1 延迟/超时时间完整性

涉及延迟、超时、重试间隔等时间相关描述时，必须补充具体时间值。

| 检测类型 | 处理方式 |
|----------|----------|
| 描述"延迟后重试"但未说明延迟多久 | 从源码查找延迟常量并补充 |
| 描述"超时后失败"但未说明超时时间 | 从源码查找超时配置并补充 |
| 描述"定期执行"但未说明执行间隔 | 从源码查找定时任务间隔并补充 |

示例修正：
- 修正前：`msgCount > 1000 → 暂停拉取（消息数量太多）`
- 修正后：`msgCount > 1000 → 暂停拉取（消息数量太多），延迟50ms后重试`

## 步骤5：优化执行

| 操作类型 | 说明 |
|----------|----------|
| 补充内容 | 补充缺失的章节、属性、枚举值、配置项 |
| 补充图例 | 为关键流程补充流程图/时序图/状态图 |
| 精简代码 | 精简过长代码，添加中文注释 |
| 补充单位 | 为数值补充单位，优化单位可读性 |
| 补充默认值 | 为配置项、参数补充默认值说明 |
| 合并/拆分章节 | 将相关内容合并或过大章节拆分 |
| 移动内容 | 将内容移动到正确的归属位置 |
| 补充说明 | 为标题添加简要说明 |
| 修正错误 | 修正与源码不一致的内容 |
| 添加引用 | 将重复内容改为引用链接 |

源码链接格式：`类名 ([ClassName.java](file:///path/to/ClassName.java))`

概念完整性标准：数据类需包含所有字段、枚举类需包含所有枚举值、配置类需包含所有配置项及默认值、接口类需包含所有方法签名。

## 步骤6：审查报告

**审查清单**：

| 审查类别 | 审查项 |
|----------|--------|
| 完整性 | 文件内容完整、默认值已补充、参数说明完整 |
| 结构 | 章节完整、层次清晰、粒度适中 |
| 结构一致性 | 概述与章节一致、架构图与章节一致、对比表格与章节一致 |
| 编号一致性 | 父子编号匹配、编号连续、无重复 |
| 图例 | 关键流程有图例、图例类型正确、图例清晰 |
| 代码 | 代码精简、有中文注释、格式统一 |
| 数值单位 | 数值有单位、单位可读性好、单位一致 |
| 内容 | 无重复、归属正确、术语一致 |
| 内容流畅度 | 逻辑连贯、无跳跃、层级合理 |
| 源码 | 字段/枚举/默认值一致、数值带单位 |
| 时间完整性 | 延迟/超时/重试间隔有具体时间值 |
| 完整性 | 源码链接完整、核心概念属性完整、章节有简要说明 |

**报告格式**：

```markdown
## [文件名] 审查报告

### 审查结果
| 审查类别 | 状态 | 问题数量 |
|----------|------|----------|
| 完整性 | ✅/⚠️/❌ | N |
| 结构 | ✅/⚠️/❌ | N |
| 图例 | ✅/⚠️/❌ | N |
| 代码 | ✅/⚠️/❌ | N |
| 数值单位 | ✅/⚠️/❌ | N |
| ... | ... | ... |

### 问题列表
| 序号 | 问题类型 | 位置 | 描述 | 处理方式 |

### 优化记录
| 序号 | 操作类型 | 位置 | 内容摘要 |
```

---

## 注意事项

- 所有信息必须来自源码，禁止凭记忆或推测，每个概念标注源码位置
- 优化前备份原文档内容，优化后验证文档可读性和逻辑性
- 跨文件优化时注意引用关系的正确性
- 关键流程必须配有图例，便于读者理解
- 代码示例要精简且有中文注释
- 数值必须带单位，单位表述要统一且可读
