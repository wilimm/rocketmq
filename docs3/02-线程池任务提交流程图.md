# 线程池任务提交流程图

## execute()方法处理流程

线程池通过execute()方法提交任务，根据当前线程数和队列状态采取不同策略。

```mermaid
flowchart TD
    A["execute(Runnable command)"] --> B{"当前线程数 < corePoolSize?"}
    
    B -->|"是"| C["创建核心线程执行任务<br/>addWorker(command, true)"]
    B -->|"否"| D["尝试将任务加入工作队列<br/>workQueue.offer(command)"]
    
    C --> E{"创建成功?"}
    E -->|"成功"| F["任务已执行"]
    E -->|"失败"| G["任务拒绝<br/>reject(command)"]
    
    D --> H{"入队成功?"}
    H -->|"成功"| I["任务已入队等待"]
    H -->|"失败"| J{"当前线程数 < maximumPoolSize?"}
    
    J -->|"是"| K["创建非核心线程执行任务<br/>addWorker(command, false)"]
    J -->|"否"| L["任务拒绝<br/>reject(command)"]
    
    K --> M{"创建成功?"}
    M -->|"成功"| N["任务已执行"]
    M -->|"失败"| L
    
    I --> O["等待空闲线程获取执行"]
    
    style A fill:#e3f2fd
    style B fill:#e1bee7
    style C fill:#c8e6c9
    style D fill:#bbdefb
    style G fill:#ffcdd2
    style L fill:#ffcdd2
    style O fill:#fff9c4
```

## 任务提交流程说明

| 步骤 | 条件 | 操作 | 说明 |
|------|------|------|------|
| 1 | 线程数 < corePoolSize | 创建核心线程 | 直接执行任务，无需入队 |
| 2 | 线程数 >= corePoolSize | 任务入队 | 任务进入工作队列等待 |
| 3 | 入队失败且线程数 < maximumPoolSize | 创建非核心线程 | 创建临时线程执行任务 |
| 4 | 入队失败且线程数 >= maximumPoolSize | 拒绝任务 | 执行拒绝策略 |

## 拒绝策略

当任务无法被接受时，执行拒绝策略：

```mermaid
flowchart LR
    A["任务被拒绝"] --> B{"拒绝策略类型"}
    
    B -->|"AbortPolicy"| C["抛出RejectedExecutionException"]
    B -->|"CallerRunsPolicy"| D["由调用线程执行任务"]
    B -->|"DiscardPolicy"| E["直接丢弃任务"]
    B -->|"DiscardOldestPolicy"| F["丢弃队列最老任务<br/>重新提交当前任务"]
    
    style C fill:#ffcdd2
    style D fill:#c8e6c9
    style E fill:#fff9c4
    style F fill:#bbdefb
```

## 四种拒绝策略对比

| 策略 | 行为 | 适用场景 |
|------|------|---------|
| AbortPolicy | 抛出异常（默认） | 需要感知任务被拒绝的场景 |
| CallerRunsPolicy | 调用者线程执行 | 需要保证任务不丢失 |
| DiscardPolicy | 静默丢弃 | 可容忍任务丢失 |
| DiscardOldestPolicy | 丢弃最老任务 | 优先处理新任务 |

## 关键概念

- **核心线程**：常驻线程，即使空闲也不会被回收（除非allowCoreThreadTimeOut=true）
- **非核心线程**：临时线程，空闲超过keepAliveTime后会被回收
- **工作队列**：缓冲区，解耦任务提交与执行速度差异
- **拒绝策略**：任务无法接受时的处理方式
